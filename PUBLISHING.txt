ONE SOURCE, ONE BUILD
A newly approved artifact has one canonical HTML source containing its exact words,
title, author, stable URL, type, dates, approval reference, citations, and supplied
relationships. Do not separately edit the Library, catalog, search index, feed,
sitemap, or integrity hashes.

Run:
  python scripts/build-corpus.py
  python scripts/check-corpus.py
  python scripts/build-corpus.py --stage ../governedlogic-public-candidate

The build derives the Library, catalog, full-text search, sitemap, feed, manifest,
and integrity records. It injects no Explore interface, fixed navigation bar,
pervasive Library link, or presentation copy into canonical pages.

PUBLICATION METADATA
New approved HTML requires a route-matching HTTPS canonical URL, visible h1,
author, exact visible description, gl-status, gl-approval, gl-type, and consistent
JSON-LD with real publication/revision dates. Missing required metadata fails.
Draft or unapproved content is excluded. Previously published v19.2 routes remain
explicitly grandfathered without invented historical metadata.

STAGING BOUNDARY
Never deploy the authoring directory or commit private drafts to the public repo.
Only a fresh staged package may be copied to main after explicit release approval.
The stage contains approved canonical HTML, derived machine-readable outputs,
directly referenced public assets, CNAME, robots, and existing source editions.
It excludes scripts, requirements, tests, drafts, review records, and unreferenced
files. A public link to unapproved HTML causes staging to fail.

HUMAN EXPERIENCE BOUNDARY
Machine-readable discovery remains underneath the presentation. Publication intake
must not redesign the human experience or automatically expose every relationship
as visible navigation. Visual scene data, if introduced, must be derived from
canonical sources and must pass the human-experience requirements contract.

REPRODUCIBILITY
  python scripts/build-corpus.py --check
fails if derived bytes are stale. check-corpus.py checks deterministic output,
canonical routes, duplicate IDs, local links/fragments, JSON-LD, catalog/search
agreement, source and HTML hashes, approved intake, metadata rejection, draft
exclusion, and restoration after removing a fixture.

RELEASE EVENTS
Presentation builds do not create publication or substantive-revision dates.
Build time never replaces an authored release event. Claims of deployment, indexing,
training inclusion, propagation, device validation, or accessibility remain tied to
actual evidence. Existing inherited metadata mismatches remain recorded rather than
repaired with invented prose.
